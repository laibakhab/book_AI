# Data Model: Physical AI & Humanoid Robotics

## Entities

### Command
- **Description**: Natural language input from the user that needs to be processed and executed by the robot
- **Attributes**: 
  - `id`: UUID (unique identifier)
  - `text`: String (the natural language command)
  - `type`: Enum (text, voice)
  - `timestamp`: DateTime (when the command was received)
  - `status`: Enum (pending, processing, completed, failed)
  - `user_id`: UUID (identifier of the user who issued the command)

### Plan
- **Description**: Structured sequence of actions generated by the AI planning layer that the robot will execute
- **Attributes**:
  - `id`: UUID (unique identifier)
  - `command_id`: UUID (reference to the original command)
  - `actions`: List[Action] (sequence of actions to execute)
  - `status`: Enum (pending, executing, completed, failed)
  - `created_at`: DateTime
  - `completed_at`: DateTime (nullable)

### Action
- **Description**: Individual action within a plan that the robot should execute
- **Attributes**:
  - `id`: UUID (unique identifier)
  - `type`: Enum (navigate, grasp, manipulate, wait, speak)
  - `parameters`: Dict (parameters specific to the action type)
  - `status`: Enum (pending, executing, completed, failed)
  - `execution_order`: Integer (order in which the action should be executed)

### Environment
- **Description**: Simulated physical space (using Gazebo/Isaac Sim) where the robot operates and navigates
- **Attributes**:
  - `id`: UUID (unique identifier)
  - `name`: String (name of the environment)
  - `description`: String (textual description)
  - `world_file_path`: String (path to Gazebo world file)
  - `objects`: List[Object] (objects that exist in this environment)
  - `robot_spawn_position`: Vector3 (default position for robot spawning)

### Object
- **Description**: Physical entities in the simulated environment that the robot can perceive and interact with
- **Attributes**:
  - `id`: UUID (unique identifier)
  - `name`: String (name of the object)
  - `type`: String (classification of the object)
  - `position`: Vector3 (current position in the environment)
  - `properties`: Dict (physical properties like color, size, weight)
  - `environment_id`: UUID (reference to the environment this object belongs to)

### Robot
- **Description**: Simulated humanoid robot with perception, navigation, and manipulation capabilities
- **Attributes**:
  - `id`: UUID (unique identifier)
  - `name`: String (name of the robot model)
  - `model_file_path`: String (path to robot URDF/SDF model)
  - `current_position`: Vector3 (current position in the environment)
  - `current_orientation`: Quaternion (current orientation)
  - `sensors`: List[Sensor] (sensors mounted on the robot)
  - `actuators`: List[Actuator] (actuators available on the robot)

### Sensor
- **Description**: Sensors mounted on the robot for perception capabilities
- **Attributes**:
  - `id`: UUID (unique identifier)
  - `type`: Enum (camera, lidar, imu, force_torque)
  - `name`: String (name of the sensor)
  - `topic_name`: String (ROS topic for sensor data)
  - `robot_id`: UUID (reference to the robot this sensor is mounted on)

### Actuator
- **Description**: Actuators available on the robot for manipulation capabilities
- **Attributes**:
  - `id`: UUID (unique identifier)
  - `type`: Enum (joint, gripper, wheel)
  - `name`: String (name of the actuator)
  - `topic_name`: String (ROS topic for actuator commands)
  - `robot_id`: UUID (reference to the robot this actuator belongs to)

## State Transitions

### Command States
- `pending` → `processing` → `completed` | `failed`

### Plan States
- `pending` → `executing` → `completed` | `failed`

### Action States
- `pending` → `executing` → `completed` | `failed`

## Relationships
- A Command generates one Plan
- A Plan contains many Actions
- An Environment contains many Objects
- A Robot has many Sensors and Actuators
- An Object belongs to one Environment
- A Sensor/Actuator belongs to one Robot

## Validation Rules
- A Command text must not be empty
- A Plan must contain at least one Action
- An Environment must have a valid world file path
- Object positions must be within environment bounds
- Robot spawn position must be in a valid location within the environment
- Action parameters must be valid for the action type
